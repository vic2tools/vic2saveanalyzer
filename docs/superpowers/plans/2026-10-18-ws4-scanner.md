# Workstream 4: The Rust Scanner. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The scanner (`scanner/src/`, 18,938 lines) gets simpler without
changing a single output. The work:
- dead code and a dependency-free MD5 go;
- the front builds the engine's `Run` directly, instead of writing JSON the
  engine parses back;
- stringly variants become enums;
- each rule has one owner;
- the `src/` root and the three biggest files are split by responsibility;
- comments stop describing the Python handover that ended on 1 Oct.

**Architecture:**
- **Pure moves come before rewrites.** Task 3 puts every file where it ends
  up, and changes nothing but `mod`/`use` lines and paths. Later tasks then
  rewrite code in its final home, and their diffs show only real changes.
- **One output check for every commit.** The recorded answers
  (`testkit/expected/`) and the maintainer's baseline hold the CSVs, payload,
  stdout and stderr to the byte. The cache keys and `report.stamp` are the
  only bytes allowed to change (Decisions).

**Tech Stack:**
- Rust 2021, no crates. Build with
  `~/.cargo/bin/cargo build --release --manifest-path scanner/Cargo.toml`.
- The test kit: `all.py`, `mutate.py` with `mutations.py`, `docrefs.py`,
  `pagebuild.py`, `staleness.py`, `frontcheck.py`, `caching.py`,
  `enginecompress.py`, and the unit tests.

**Spec:** `docs/superpowers/specs/2026-10-16-repo-cleanup-design.md`, workstream 4, Decisions, and the Verification bar.

## Global Constraints

- **No output change.** Every CSV, the report payload, stdout and stderr stay
  identical. "A cleanup that shifts a number is a failed cleanup." Only these
  bytes may change:
  - the cache keys and entry format: they already include `VIC2_BUILD_ID`;
  - `report.stamp`.
- **No crate dependencies in `scanner/`.**
- **After every commit:**
  - rebuild;
  - `python testkit/all.py "$S" --mod "$M" --baseline ~/vic2-baseline` holds:
    all checks, the baseline still run with its
    `--ignore payload.wars[].side_losses`;
  - `python testkit/mutate.py --dry` shows 0 NOAPPLY;
  - every mutation whose patched code moved or changed is run and CAUGHT
    (`mutate.py --only NAME…`).
- **At the end:** the full mutation run catches everything except
  `keeper-folder-windows-only`.
- **No file over 1,000 lines without a reason** written at the top of that
  file.
- **Where a spec item turns out wrong on closer reading** (the copies really
  differ, or the "dead" code is reached), skip it. Say so in the commit
  message and in the ledger.
- **Machine.**
  - Windows. Run one heavy command at a time: the PC hard-resets under heavy
    load.
  - cargo is at `~/.cargo/bin`.
  - Nothing is pushed.
- **Branch and commits.**
  - Work on local branch `cleanup/scanner` from `main` (`62f44ee`).
  - Commit messages are plain sentences, ending with
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A cache entry made under other settings must stay a miss.** Once the
   context is hashed from typed fields (Task 4), a run that changes only
   `--mob-types`, `--player-nations`, `--min-pop`, a tag filter or the mod's
   strata must miss. If it hit, it would answer with the earlier settings'
   numbers. Test in Task 4.
2. **`--no-html` and the diagnostics never decode the map.** The raster stops
   being optional (Task 1). A run that writes no page must neither decode the
   map nor reach a path that assumes it was decoded. Test in Task 1.
3. **A mod refused in words versus one that cannot be read.** `Decline`
   becomes an enum (Task 5). The sentence a user sees for each must be
   unchanged, including through the "the mod:" and "the map or the flags:"
   prefixes. The records in `frontcheck` hold the refusals. Task 5 adds a
   unit test of the prefixes.
4. **The cache folder is the window's.** The cache path moves from Rust's
   `gettempdir` to the launcher (Task 2). The window's "empty the cache" must
   still find the scanner's entries, and `TMPDIR` must still redirect them.
   `caching.py` holds this; Task 2 runs it.
5. **The mod signature must still change** when a mod file is edited, added
   or removed, and come back when the edit is reverted. This holds after MD5
   becomes the two-lane hash and the `mod-signature` mode goes. Task 2 moves
   `frontcheck`'s signature check onto `report.stamp`.
